# 课后模式

当用户明确说“课后模式”，或要求把一节课的录音／转写和可选个人笔记整理成课程笔记时，使用本流程。该模式负责一次课的归档、转写、知识重构、分类和索引；长期路线、掌握度和复习由学习项目的计划与状态文件负责（见 [goal-and-map.md](goal-and-map.md) 和 [learner-state.md](learner-state.md)）。

## 交付结果

一次完整运行至少交付：

1. 独立保存的原始材料包；
2. 录音对应的可核对转写；
3. 一份默认 Markdown 格式的结构化课程笔记；
4. 课次／日期、知识形态、处理模式和主题标签；
5. 按课次和日期排序的课程索引。

讲透模式只有在用户确认后才增加外部研究、来源地图和质询；课后模式本身不自动开启讲透模式。

## 课次与时间标识

每个课后单元至少需要**课次或日期**之一，二者都有时一起使用。

可靠性顺序：

1. 用户明确给出的课次／日期；
2. 课程目录、文件名或用户笔记中明确写出的课次／日期；
3. 录音媒体元数据中的可靠录制时间；
4. 项目中已有连续课次可以无歧义推出的下一课。

文件系统修改时间不能单独作为上课时间。缺少可靠标识、多个文件可能属于不同课次或推断会改变归档位置时，合并成一个问题询问用户。

会话标识格式：

- 课次和日期都有：`L03_2026-10-12`
- 只有课次：`L03`
- 只有日期：`2026-10-12`

课次使用正整数和至少两位补零。标题不进入 `session_id`，只进入笔记文件名和元数据。

## 默认目录

课程已有明确约定时适配原结构；否则在课程根目录使用：

```text
<course-root>/
├── 00_course_index.md
├── 01_raw/
│   └── L03_2026-10-12/
│       ├── originals/
│       │   ├── lecture.m4a
│       │   └── user-notes.md
│       ├── transcript.md
│       └── session.json
└── 02_notes/
    └── L03_2026-10-12_遗漏变量偏误.md
```

- `originals/` 保存输入文件的原始副本；不改名、不覆盖、不删除来源文件。
- `transcript.md` 是从录音产生的派生材料，不冒充原始音频。
- `session.json` 记录课次、日期、标签来源、文件哈希和预期笔记路径。
- `02_notes/` 只放整理后的学习资产，不混放音频或转写。

## 完整流程

### 1. 归并同一课次的输入

确认哪些录音、转写、讲义和用户笔记属于同一节课。多个录音片段可以属于同一课次；明显属于不同日期或不同课次时分别建会话，不合并为一篇。

用户笔记是可选输入，主要用于发现：

- 用户当时记录的重点；
- 板书、页码、公式和老师口头指代；
- 录音中听不清的专有名词；
- 用户自己的疑问或待补部分。

用户笔记可能遗漏或记错，不能在冲突时自动覆盖录音、讲义或教材。无法判断时保留两种说法并标记待核实。

### 2. 建立原始材料包

从 Skill 根目录运行：

```bash
python3 scripts/prepare_after_class.py \
  --course-root <课程根目录> \
  --course <课程名称> \
  --lesson 3 \
  --date 2026-10-12 \
  --title <本课主题> \
  --label-source user \
  --source <录音文件> <用户笔记文件>
```

日期或课次缺少时省略对应参数，但二者不能同时缺少。脚本默认复制文件；同名同内容可重复执行，同名不同内容会停止并报错。

脚本返回 `session_id`、原始材料目录和预期笔记路径。不要在脚本运行前手工移动或删除来源文件。

### 3. 转写并核对

对音频或视频使用环境中可用的语音转写能力。没有可用转写能力时，完成原始材料归档后停止，报告尚缺转写，不能根据文件名生成课程内容。

把转写保存为对应会话的 `transcript.md`，至少包含：

- `session_id`、课程名称和转写来源；
- 是否为自动转写；
- 无法辨认、时间戳或说话人信息（工具能够提供时）；
- 未经知识重构的连续转写正文。

整理前用用户笔记、讲义和上下文核对人名、术语、数字、公式和正负号。无法确认的内容在转写和笔记中标为待核实。

### 4. 建立画像并生成笔记

按 [unit-workflow.md](unit-workflow.md) 执行知识重构；其中按 [course-routing.md](course-routing.md) 自动判断知识形态和处理模式，按 [mode-guides.md](mode-guides.md) 组织内容。笔记必须以以下 frontmatter 开头：

```yaml
---
title: "本课标题"
course: "课程名称"
mode: "after-class"
session_id: "L03_2026-10-12"
lesson: 3
date: "2026-10-12"
source_bundle: "../01_raw/L03_2026-10-12/"
knowledge_types:
  - 概念性
  - 程序性
learning_modes:
  - 概念与理论
  - 定量与问题求解
tags:
  - 课后笔记
  - 课程主题标签
---
```

实际开启讲透模式时再增加 `depth_mode: "deep"`；普通课后笔记不写该字段，也不暗示已经做过外部研究。

只有日期或课次时省略不存在的字段，不写空字符串。分类规则：

- `knowledge_types` 只能从事实性、概念性、程序性、元认知中选择；
- `learning_modes` 只能从六种处理模式中选择，按主要到次要排序；
- `tags` 包含 `课后笔记`、课程主题和真正有检索价值的关键词，不把所有小标题做成标签；
- 分类根据本节材料，而不是只根据课程名称。

正文使用 Skill 的动态结构，至少回答：这节课解决什么问题、知识如何连接、哪里容易错、怎样在不看材料时重建。没有考试范围或老师明确提示时，不写“必考”。

### 4.1 可选的讲透增强

用户已确认讲透模式时，在完成课堂候选结构后读取并执行 [deep-explanation-mode.md](deep-explanation-mode.md)：以本节课为锚建立知识缺口图，调用可用研究能力补充、核实和集成外部来源，再对候选笔记执行多 Agent 或降级的分角色质询。

课堂内容和外部补充必须保持可辨认边界。外部研究较多或资料具有时效性时，在会话包根目录保存 `research.md`，记录访问日期、链接、来源角色、支持的主张和未解决冲突；不把它放入 `originals/`，也不下载和复制无必要的整份网页。

### 5. 验证并更新索引

笔记完成后依次运行：

```bash
python3 scripts/validate_learning_asset.py <笔记路径>
python3 scripts/refresh_course_index.py --course-root <课程根目录>
```

索引默认写入 `00_course_index.md`，按日期和课次排序，列出主题、分类、笔记、原始材料和状态。若已有同名文件但不是该脚本生成的文件，脚本拒绝覆盖。

课程根目录同时是学习项目（存在 `00_learning_plan.md`）时，再按 [learner-state.md](learner-state.md) 更新本课节点的等级和复习队列。

## 验收清单

- 原始音频和用户笔记保留在会话的 `originals/` 中，哈希记录完整；
- 转写与原始音频分开，并标明自动转写和待核实内容；
- 输出笔记位于 `02_notes/`，文件名含 `session_id`；
- frontmatter 中的课次、日期和目录一致；
- 分类标签来自本课内容且只使用允许值；
- 用户笔记中的独有重点已核对，冲突没有被静默覆盖；
- 课程索引包含这一课并能链接到笔记和原始材料；
- Markdown 与公式检查通过。
- 未经确认没有启动讲透模式；确认开启时，笔记标记 `depth_mode: "deep"`，关键外部主张可追溯，研究记录与原件分开。

交付时列出原始材料包、转写、课程笔记和索引的路径，并说明课次／日期的来源、是否开启讲透模式、质询方式及任何待核实项。
