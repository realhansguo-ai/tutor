# 建档：目标、领域地图与起点

建档把“我想学会 X”变成一个可执行、可检验的学习项目。它决定后续每个环节学什么、跳过什么、先学什么，以及用什么检验学会了。按顺序执行以下步骤；每步的完成标准满足后再进入下一步。

## 1. 把目标改写为目标任务

从用户表述、课程大纲、考试信息和材料中提取学习目的、截止时间、可投入时间和已有基础。常见目的及其目标任务来源：

| 学习目的 | 目标任务从哪里来 |
| --- | --- |
| 通过一场考试 | 官方考纲、真题、题型、分值和评分标准 |
| 学好一门课 | 教学大纲、作业、往年试题、老师明确的要求 |
| 读懂某类文献或资料 | 该领域有代表性的论文、报告或文本 |
| 在工作或研究中使用 | 用户的真实问题、典型场景和交付物 |
| 建立领域整体框架 | 能用领域核心问题组织知识，并解释、比较代表性理论或方法 |

把目的改写为 3—8 个目标任务。每个目标任务写明：学习者要做什么、在什么条件下（是否闭卷、时间限制、材料类型）、怎样判定完成。考试目标的判定直接使用考试的题型和评分方式；其他目标写出评分维度，没有外部标准时自设通过线，标注“自设”，并允许学习者调整。

信息缺失且会改变路线时，把截止时间、目的和可选的偏好（如感兴趣的应用领域）合并为一个问题询问；用户不回答时采用 `SKILL.md` 的默认值，并在计划中注明“假设”。学习者的基础不靠询问确定，交给第 4 步诊断。

**完成标准：** 每个目标任务都是可观察的表现并附判定方式；“理解”“掌握”“熟悉”这类词只出现在被具体任务解释过的地方。

## 2. 确定来源

盘点用户提供的材料，按 [source-and-output.md](source-and-output.md) 记录来源清单。

用户没有材料或材料不足以覆盖目标任务时，主动寻找来源，优先级为：

1. 考试机构或课程的官方考纲、真题、评分标准；
2. 领域公认的教材及其目录、配套习题；
3. 一流大学公开课程的大纲、讲义和习题；
4. 权威综述、手册、官方文档和标准；
5. 高质量讲解、博客和开源材料，用于直觉和例子，不单独支撑关键事实。

只记录实际读到或核实过的来源，注明读到的范围（目录、某章、全文）。搜索失败、付费墙或无法联网时说明限制，用已有材料完成可完成的部分。考试类目标拿不到官方考纲或真题时，在计划中写明“未对齐官方考试范围”。

**完成标准：** 每个目标任务至少有一个来源能说明它要求什么知识；来源清单中没有未读却被当作依据的条目。

## 3. 绘制领域地图

把领域拆成知识节点。一个节点是能在一次专注学习中学完并检验的单位，例如“遗漏变量偏误的方向判断”，而不是“回归分析”。为每个节点记录：

- 名称和一句话内容；
- 前置节点；
- 角色：**核心**（目标任务直接使用）、**支撑**（核心节点的前置）、**边缘**（有助于理解但目标任务不直接依赖）；
- 服务的目标任务及权重依据（考纲分值、真题频次、老师强调、任务必需）；没有依据时不编造权重；
- 典型误解或易混节点。

节点数量随领域范围变化。一门学期课程通常 20—60 个节点；节点过多时按章节分组，组内再列节点。

没读到正文支撑的节点标“待核实”，不要把整张地图包装成来自某本教材。

**完成标准：** 每个目标任务都能追溯到一组节点；每个节点要么服务某个目标任务，要么是某个服务节点的前置，否则删除或标为边缘；依赖关系中没有循环。

## 4. 诊断起点

用诊断题确定学习者在核心和支撑节点上的起点，而不是询问“这个你会不会”。诊断要等待学习者作答，开始前先按第 6 步的格式写入 `00_learning_plan.md` 中已完成的目标任务、来源和领域地图，学习路线一节标注“待诊断后排定”，并创建 `00_learner_state.md`（节点全部记为“未诊断”），避免会话中断时丢失建档成果。有截止时间时，同时给出粗略的时间可行性判断：可用总时长与核心节点数量是否匹配。

- 优先诊断地图中下游最多的节点：它们没掌握，后续都受影响；
- 每题检验理解或应用，不只检验能否背出名词；
- 通常共 5—10 题，按 [practice-and-feedback.md](practice-and-feedback.md) 的分批规则和交互方式让学习者作答并批改；诊断题可以自编，情境为虚构时注明；
- 按批改结果给节点定级；答对一个前置节点的应用题，可以把它的更底层前置一起标为“能应用”，并注明是推断。

学习者拒绝或没时间诊断时，所有节点记为“未诊断”，从最底层前置开始；在后续练习中逐步定级。

**完成标准：** 每个核心节点都有掌握等级或“未诊断”标记；每个等级都写明依据。

## 5. 排定学习路线

按以下顺序排列待学节点：

1. 前置在先：节点的前置没有达到“能应用”时，先学前置；
2. 在满足依赖的节点中，优先“目标权重高且当前差距大”的；
3. 已有证据证明达到“能应用”的节点只进入复习，不再作为新单元学习；
4. 边缘节点放在最后，或在时间不足时删去。

把相邻节点合成学习单元，并估计每个单元的投入。用户给出截止时间和可投入时间时，按周分配单元，留出复习和阶段验收的时间；时间不足以覆盖全部核心节点时直接说明，给出按权重取舍后的版本。路线是节点顺序加节奏，不是逐日打卡表；用户明确要求逐日安排时再细化。时间估计标为“假设”，诊断后修正；时间不够时先删边缘节点，再压缩低权重支撑节点，并事先写明会先删哪些。

从来源中预留一组**留出验收题**：真题、教材习题或代表性任务，学习和练习中不使用，只在阶段验收时使用。还没有读到可用的题目或材料时，写明“尚未选定”、需要的类型和计划在何时选定，不凭记忆列出未核实的题目或文献。

**完成标准：** 路线中的每个单元都能说出它解决哪些节点、为什么排在这个位置；时间不足时的取舍已经写明。

## 6. 写入项目文件

创建 `00_learning_plan.md` 和 `00_learner_state.md`（格式见 [learner-state.md](learner-state.md)）。计划文件结构：

```markdown
---
project: "领域或课程名"
goal: "一句话学习目的"
deadline: "2026-12-20"     # 没有时省略
created: "2026-10-15"
updated: "2026-10-15"
---

# 学习计划：领域或课程名

## 目标任务
| 编号 | 目标任务 | 条件 | 判定方式 |

## 来源
| 来源 | 类型 | 读取范围 | 用途 |

## 领域地图
按章节分组；每个节点一行：编号、节点、角色、前置、服务的目标任务、权重依据、典型误解。

## 学习路线
按顺序列出学习单元、包含节点、预计投入、排序理由。

## 留出验收题
题目来源和位置；题目原文另存于 `04_checks/`，避免学习时看到。

## 假设与待核实
```

建档完成后告诉学习者：目标任务、起点诊断结论、第一个学习单元，以及路线中最大的风险（例如时间不足、缺少官方考纲）。用户愿意时直接进入第一个学习单元。
